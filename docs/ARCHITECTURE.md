# 关键设计与生命周期

1. 一套核心维护视频/搜索/评论/设置模型；三个主题只提供 tokens 与受限布局变体。桌面 Shell 包含应用栏、会话列表、聊天主区；企微宽屏增加群信息栏，聊天主区再分会话头部、消息滚动区和输入栏。切换外观仅更新根属性；切换主题重建 Shell 并刷新当前路由的数据，避免主题专属会话名和消息内容残留。主题切换会停止旧播放器。
2. Shell 覆盖原站，保持宿主 DOM 和原生框架挂载点；不搬移播放器，也不把宿主异常当作无关日志。后台宿主视频在办公模式暂停。
3. 播放时创建一个带随机令牌的 `www.bilibili.com/video/BV...` iframe；该 iframe 只运行播放器桥，不启动 Shell。搜索域和主站域不能互读 iframe DOM，由固定来源、source、令牌、类型校验后的消息传状态和评论。进度拖动直接使用 iframe 内的原生播放器控件，外层不创建进度条，也不发送 seek 命令。桥只显示实际播放器根容器，保留后代元素的原生显隐与交互规则；悬停或键盘聚焦时确保原生控制栏可见，隐藏弹幕输入栏以保留视频画布。父页面继续验证播放状态消息的时间、时长和区间字段。
4. 放大使用同一节点的 fixed 定位和遮罩；没有重挂载、Popover 容器迁移或视频 DOM 搬运。评论区的 `replaceChildren` 不涉及视频卡片。常规卡片同步按 ID 更新文本；明确刷新或路由变化才清空列表。
5. 全局监听器由实例 AbortController 或会话 cleanup 管理；路由变化先中止旧请求，销毁 iframe、计时器、遮罩和弹窗，再更新新列表。隐藏媒体采用销毁策略处理加载中和已加载播放器，恢复不会自动播放。
6. 原站列表等待只观察已有的 `#app` / `#i_cecream` / `main` 宿主，节流并在结果到达、4秒超时或取消时释放。视频桥按650ms检查视频，评论通过同频率的宿主范围轮询自动同步，不遍历整站；详情页也使用该评论观察流程，路由取消与 iframe 卸载都会释放轮询。评论懒加载通过在后台将评论宿主临时固定到视口内触发，加载完成、超时或取消即恢复宿主布局。整个过程不滚动原站文档，避免固定播放器的原生进度条坐标错位。加载更多等待真实评论变化，最多10秒并可取消。
7. 新搜索、排序或翻页先中止旧请求并显示等待，不把旧内容当新结果。初始搜索 DOM 回退仅匹配本次载入时的关键词、排序和页码；否则调用接口，失败公开显示状态和原版加载入口。

8. `Workspace` 管理飞书与企微各自的本地会话数据。企微独立样式位于 `src/styles/wecom.css`，按用户提供的真实企微截图使用蓝灰应用栏、白色会话列表、蓝色会话选中态、白色画布与浅灰气泡。宽屏常驻群公告、看板和成员列表，窄屏通过会话详情入口访问；分组放在应用栏，视频搜索收进列表顶部加号。`src/components/wecom.ts` 提供原创 SVG 图标与头像，不加载外部图像服务。会话搜索与视频搜索分开；未读、提及、单聊/群聊筛选、置顶、免打扰、草稿和引用回复在当前实例内维护。输入区的发送仅追加本地消息，不调用企业微信或 B 站的发送接口，刷新页面后恢复样例数据。企微切换会话时停止播放器，飞书沿用隐藏会话但保留播放器节点的行为。
